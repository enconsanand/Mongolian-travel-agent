# Database / Өгөгдлийн сан

MongoDB database of the Mongolia travel agent: what is in it, what the mock data contains, and the schema of every collection.
Монгол аяллын агентын MongoDB өгөгдлийн сан: юу хадгалдаг, mock өгөгдөлд юу байгаа, collection бүрийн schema.

- Schema (source of truth / цорын ганц эх сурвалж): [`back/app/schemas/travel.py`](../back/app/schemas/travel.py)
- Mock data / Mock өгөгдөл: [`data/mock/`](../data/mock/) (generated by `generate.py`)
- Connection, indexes / Холболт, индекс: [`back/app/db/mongo.py`](../back/app/db/mongo.py)
- Validators: [`back/app/db/validators.py`](../back/app/db/validators.py)
- Read API: [`back/app/api/v1/travel.py`](../back/app/api/v1/travel.py)

## 1. Quick start / Эхлэх

```bash
# secret/.env: SEED_DEV_PASSWORD=<password for the demo logins>, optional MONGO_URI=<Atlas URI>
make build
make seed        # loads data/mock, creates login users, validators and indexes
make up          # API on http://localhost:8000/api/v1 (docs: /docs)
make seed-reset  # dev only: also wipes trips/bookings/payments/availability back to the demo data
```

EN: `make seed` validates every mock file against the schema first; if any file is wrong nothing is changed. Reference collections (stays, routes, events, ...) are rebuilt under a temporary name with their validator and indexes, then swapped in. Stateful collections (trips, bookings, payments, refunds, conversations, ... and the availability of rooms, seats, cars and shared rides) keep their data; only demo rows that are missing are added. Safe to run again. The backend also creates all indexes when it starts.

MN: `make seed` эхлээд бүх mock файлыг schema-тай тулгаж шалгана; нэг нь буруу бол юу ч өөрчлөхгүй. Лавлах collection-уудыг (буудал, маршрут, арга хэмжээ...) түр нэрээр validator, индекстэй нь бүтээгээд сольж тавина. Төлөвтэй collection-ууд (trips, bookings, payments, refunds, conversations... мөн өрөө, суудал, машин, хамтын унааны сул тоо) өгөгдлөө хадгалж, байхгүй демо мөрүүд л нэмэгдэнэ. Дахин ажиллуулахад аюулгүй. Backend асахдаа бүх индексээ өөрөө үүсгэнэ.

`data/mock/import.sh`: EN: plain `mongoimport` fallback (e.g. Atlas without Docker); no validators, no login users. MN: Docker-гүй ачаалах нөөц арга; validator, нэвтрэх хэрэглэгчгүй.

## 3. Two languages / Хоёр хэл (mn + en)

EN: Every human-readable text is stored in both languages as a `Text` object:

MN: Хүн уншдаг бүх текст хоёр хэлээр `Text` объект хэлбэрээр хадгалагдана:

```json
"name": { "mn": "Хөх сувд бааз", "en": "Blue Pearl Ger Camp" }
```

- EN: Bilingual fields: names, descriptions, notes, route names and summaries, segment notes, region highlights, trip titles, quote labels, booking notes, refund reasons, departure points. They are marked **Text** in the tables below.
- MN: Хоёр хэлтэй талбарууд: нэр, тайлбар, тэмдэглэл, маршрутын нэр ба товч, замын хэсгийн тэмдэглэл, бүсийн онцлох газар, аяллын гарчиг, хувилбарын нэр, захиалгын тэмдэглэл, буцаалтын шалтгаан, хөдлөх цэг. Доорх хүснэгтэд **Text** гэж тэмдэглэсэн.
- EN: Codes stay as codes (`type`, `status`, `amenities`, `hazards`, `surface`, `region`, ...). The frontend shows their labels.
- MN: Кодууд код хэвээрээ (`type`, `status`, `amenities`, `hazards`, `surface`, `region`, ...). Дэлгэцэнд харуулах нэрийг front өөрөө орчуулна.
- EN: The API answers in one language: it reads `Accept-Language` (`mn` default, `en`) and turns every `Text` into a plain string.
- MN: API нэг хэлээр хариулна: `Accept-Language`-ийг уншаад (`mn` үндсэн, `en`) `Text` бүрийг энгийн текст болгоно.
- EN: Mongolian translations of the generated English text live in `data/mock/translations.mn.json`; `generate.py` fails if one is missing.
- MN: Монгол орчуулга `data/mock/translations.mn.json`-д; орчуулга дутвал `generate.py` алдаа заана.

## 4. Conventions / Дүрэм

|           | EN                                                                              | MN                                       |
| --------- | ------------------------------------------------------------------------------- | ---------------------------------------- |
| Ids       | readable strings, e.g. `stay_khatgal_camp_blue_pearl`; API returns them as `id` | уншигдахуйц string, API `id` гэж буцаана |
| Dates     | `"2026-10-03"`; timestamps `"2026-10-03T08:00:00Z"`                             | ISO string                               |

| Mock flag | `is_mock: true` on generated docs                                               | үүсгэсэн document-д `is_mock: true`      |

- **east / зүүн:** Khentii, Dornod, Sükhbaatar
- **south / өмнөд:** Ömnögovi, Dundgovi, Dornogovi, Govisümber, Bayankhongor
- **hub:** Ulaanbaatar. EN: routes and schedules that start in UB take the region of their destination. MN: УБ-аас гарах маршрут, хуваарь нь очих газрынхаа бүсийг авна.

## 7. Booking and payment flow / Захиалга ба төлбөрийн урсгал

EN: 1) The agent searches reference data (stays with free units, seats left, free vehicles, events). 2) It writes 2–3 `quotes` for the trip. 3) The user accepts one; the trip gets `bookings` (status `pending_payment`). 4) The user approves the amount (`payments.consent`), the agent pays, bookings become `confirmed`. 5) On cancellation a `refunds` doc is created. Every step goes into `audit_log`.

MN: 1) Агент лавлах өгөгдлөөс хайна (сул буудал, суудал, машин, арга хэмжээ). 2) Аялалд 2–3 `quotes` бичнэ. 3) Хэрэглэгч нэгийг сонгоход `bookings` үүснэ (`pending_payment`). 4) Хэрэглэгч дүнг зөвшөөрнө (`payments.consent`), агент төлж, захиалга `confirmed` болно. 5) Цуцалбал `refunds` үүснэ. Алхам бүр `audit_log`-д бичигдэнэ.

EN (as implemented for stays): `POST /me/trips/{id}/checkouts` holds every night (`holds`, `stay_availability.available` decremented, bookings `held`) and returns the merchant-signed checkout → the browser signs an AP2 Payment Mandate → `POST /me/checkouts/{id}/pay` opens the QPay invoice → the QPay callback is verified and writes `payment.paid` to `outbox` → the booking handler confirms holds and bookings and sets the trip `booked`. Unpaid checkouts expire after 15 minutes: the invoice is closed and the units are returned. A payment that lands after its holds lapsed takes the units again, or cancels every booking of the checkout and flags a refund.

MN (буудлын хувьд хэрэгжсэн): checkout нь шөнө бүрийг hold хийнэ → хэрэглэгч AP2 Payment Mandate-д гарын үсэг зурна → QPay invoice → callback шалгагдаж `payment.paid` outbox-д → booking баталгаажиж аялал `booked` болно. Төлөгдөөгүй checkout 15 минутад дуусч, өрөө буцна.

Payment status / Төлбөрийн төлөв: `quoted → approved_by_user → awaiting_payment → paid → (cancelled → refunded)`, or `awaiting_payment → expired / failed`

EN: Live payments go through AP2 mandates and a rail (`provider`: `qpay`, `bonum`, `sim`); `stripe_test` and `qpay_sandbox` only appear in the older mock rows. See section 12.
MN: Бодит төлбөр AP2 mandate болон rail-аар (`qpay`, `bonum`, `sim`) явна; `stripe_test`, `qpay_sandbox` нь зөвхөн хуучин mock мөрөнд. 12-р хэсгийг үз.

## 11. Collections and schema / Collection ба schema

EN: Generated from `back/app/schemas/travel.py`. **Text** = `{mn, en}`; `?` = may be null; Req ✓ = required. Every collection except `users` has a MongoDB `$jsonSchema` validator built from this schema, so wrong documents are rejected. Unknown fields are not allowed.

MN: `back/app/schemas/travel.py`-ээс үүсгэсэн. **Text** = `{mn, en}`; `?` = null байж болно; Req ✓ = заавал. `users`-ээс бусад collection бүр энэ schema-аас үүссэн MongoDB `$jsonSchema` validator-тай тул буруу document орохгүй. Тодорхойлоогүй талбар оруулахыг зөвшөөрөхгүй.

Shared types / Нийтлэг төрөл: **Text** `{mn, en}` · **Point** `{type: "Point", coordinates: [lng, lat]}` · **LineString** · **Polygon**

`users` also has login fields (not in the mock file) / нэвтрэх талбарууд: `hashed_password` (bcrypt), `is_active`, `created_at`, `updated_at` (dates) — see [`back/app/models/user.py`](../back/app/models/user.py).

#### `regions` — 4 docs

The 4 travel regions: aimags in each, rough map boundary, best months, minimum days.  
4 бүс: аймгууд, газрын зургийн ойролцоо хил, тохиромжтой сар, хамгийн бага хоног.  
_Kind / Төрөл:_ reference — mock data the agent searches / лавлах mock өгөгдөл, агент эндээс хайна

Indexes: `boundary (2dsphere)`

| Field                     | Type                                   | Req |
| ------------------------- | -------------------------------------- | --- |
| `_id`                     | str                                    | ✓   |
| `code`                    | `north` \| `west` \| `east` \| `south` | ✓   |
| `name`                    | Text                                   | ✓   |
| `boundary`                | Polygon                                | ✓   |
| `boundary_is_approximate` | bool                                   | ✓   |

## 12. Commerce collections / Худалдааны collection

EN: Written only by the running app (no mock files). Schema: [`back/app/schemas/commerce.py`](../back/app/schemas/commerce.py). `make seed` creates them with strict validators and indexes; `make seed-reset` empties them. AP2 terms follow the [Agent Payments Protocol v0.2](https://ap2-protocol.org/ap2/specification/).

MN: Зөвхөн ажиллаж буй апп бичнэ (mock файлгүй). `make seed` validator, индекстэй нь үүсгэнэ; `make seed-reset` хоосолно.

| Collection       | What / Юу                                                                                                       | Key indexes                                                     |
| ---------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `checkouts`      | The exact basket the user approves, signed by the platform (`checkout_jwt`); `checkout_hash` = AP2 transaction id | `checkout_hash` unique                                          |
| `mandates`       | AP2 Checkout / Payment Mandates as received (`sd_jwt`) and whether they verified; kept as dispute evidence        | `hash` unique; `(kind, transaction_id)` unique once used        |
| `holds`          | Units taken out of `stay_availability` until paid or expired; a sweeper returns them (no TTL: it would leak units) | `(status, expires_at)`                                          |
| `payment_events` | What QPay / Bonum / sim told us: callbacks (hints) and verified checks                                           | `(provider, provider_ref, kind)` unique: repeated callbacks = 1 |
| `user_keys`      | Public P-256 keys users' browsers created (WebCrypto); direct-mode mandates are verified against them; `_id` = RFC 7638 thumbprint | `user_id` |
| `outbox`         | Events written in the same transaction as the change (`payment.paid`, `booking.confirmed`, `hold.expired`, ...)  | `(dispatched_at, created_at)`                                   |

EN: Changes to existing collections: `payments` gains `checkout_id`, `payment_mandate_id`, `transaction_id` (unique when set), providers `qpay` / `bonum` / `sim` and statuses `awaiting_payment` / `expired` / `failed`; `bookings.status` gains `held`. All additions; the mock data is unchanged.

MN: Одоогийн collection-д: `payments`-т `checkout_id`, `payment_mandate_id`, `transaction_id`, шинэ provider, төлөв; `bookings.status`-т `held` нэмэгдсэн. Бүгд нэмэлт, mock өгөгдөл өөрчлөгдөөгүй.
